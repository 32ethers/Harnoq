# 国际化维护

[中文](i18n.md) · [English](../en/i18n.md)

## 语言选择

界面支持 `zh` 和 `en`。有效的 `?lang=` 参数优先，其次是 `harnoq_locale` Cookie，未设置时默认英文，不根据浏览器 `Accept-Language` 自动切换。显式选择保存一年，Cookie 使用 HttpOnly、SameSite=Lax，在 HTTPS 下启用 Secure。切换链接保留当前路径及查询参数。偏好属于当前浏览器，不在账号之间同步。

## 翻译边界

`app/locales/en.json` 是前后端共享的英文词典，以中文原文为键。Jinja 用 `_(原文)`，JavaScript 用 `uiText(原文)` 或标签模板；动态值在词典中用 `{0}`、`{1}` 等占位。Python 显示文字可用 `gettext(message, *values)`。页面将词典安全编码为 JSON，在应用脚本之前加载翻译脚本。

只翻译显式标记的界面文字，不扫描并替换整个 DOM。项目名称、需求、设计、证据、凭据和历史记录保留原文；编号、数据库 id、枚举值、路由和接口契约保持不变。历史自动备注也保留当时记录的语言。

新增文案时补齐英文翻译，保持占位符一致。动态内容通过文本节点显示，不能把用户输入拼进翻译 HTML。已有少量选项 HTML 是不含用户插值的固定文字。新文案优先使用完整句子，已有带内联标记的片段按原顺序翻译。

## Agent 输出语言

阶段方法仍保留一份权威规则，通过语言约定指导新文档及回复。需求汇总支持中英文标记，内部类别保持原样。英文 OpenWebUI 提示词为 `skills/openwebui-system-prompt.en.md`；中文运行时文件保留原位。两份入口说明应与当前阶段方法保持一致，英文配置页显示英文提示词。

界面语言不自动改变独立 Agent 会话的输出语言，也不翻译项目历史。在会话中指定所需语言即可；术语表约定的母语词和英文词仍须保留。

## 文档布局

根 README 为英文入口并提供中文链接。原说明文档位于 `docs/cn/`，英文版位于 `docs/en/`，图片共用 `docs/assets/`。原模块 README 分别迁入两种语言下的 `skills/`、`mcp/`、`evals/`。提示词、OpenAPI 定义和根 `AGENTS.md` 是运行及开发入口，保留原位。

行为变化应同步更新双语文档，并检查链接和锚点。`git show` 示例中的历史路径不可改成当前路径，它们对应旧提交。


语言测试覆盖选择优先级、无效参数、页面翻译、插值、词典完整性、项目内容保留、删除确认、英文需求解析及文档链接。前端冒烟测试按浏览器中的顺序加载翻译模块。
